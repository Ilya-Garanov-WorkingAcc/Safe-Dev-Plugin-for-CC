# ROADMAP.md — путь к enforcement

Пилотная конфигурация принимает ограничение осознанно: плагин ставится
вручную, не защищён managed settings и потому является страховкой и
видимостью, а не границей безопасности (ADR-001). Здесь — что и в каком
порядке снимает это ограничение.

---

## 1. Managed settings — первый и главный пункт

**Что даёт.** Закрывает T3 (RCE из клонированного репозитория) полностью и T11
(отключение контроля сотрудником) технически.

**Что нужно.** MDM или GPO на рабочих станциях и участие IT: managed-файл
настроек раскладывается централизованно и недоступен пользователю на запись.

**Что включается.**

```json
{
  "allowManagedHooksOnly": true,
  "enabledPlugins": ["secure-dev@secure-dev-marketplace"],
  "disableAllHooks": false
}
```

- `allowManagedHooksOnly` — хуки исполняются только из managed-конфигурации.
  Вредоносный `.claude/settings.json` из клона перестаёт исполняться вовсе, и
  гонка на SessionStart (ARCHITECTURE §4.3) исчезает как класс.
- `enabledPlugins` — плагин нельзя отключить через `/plugin disable`.

**Чего это не отменяет.** `secure-dev scan` остаётся: он работает до запуска
claude и полезен при работе с чужим кодом вне корпоративного контура.

**Признак готовности перехода.** Пилот закончен, доля ложных срабатываний по
каждому правилу измерена и ниже 5%, классы правил раскатаны до `strict` по
графику фазы 8.

## 2. Экспорт аудита: none → file → http → OTLP

Текущее состояние — `none`, журнал остаётся локально.

| Шаг | Когда | Что меняется |
|---|---|---|
| `file` | Раскатка на отдел | `<сетевой каталог>/<user>/<host>/YYYY-MM-DD.jsonl`. Heartbeat становится рабочим инструментом: пропала папка сотрудника за неделю — плагин не работает |
| `http` | Появление коллектора | POST на эндпоинт с токеном из переменной окружения |
| OTLP | Появление наблюдаемости | Записи как события OpenTelemetry, единый бэкенд с остальной инфраструктурой |

Смена шага — правка одной строки в `policy.json`: все три режима реализованы
в `lib/export.py` сразу.

**Чего делать нельзя.** Использовать нативные `type: "http"` хуки Claude Code
для аудита: они отправляют сырые `tool_input` и `tool_response`, то есть ровно
те секреты, которые плагин обязан вычищать.

## 3. Реестр доверия к репозиториям

**Ограничение сейчас.** Реестр локальный: доверие, выданное на ноутбуке, не
переносится на десктоп. При двух-трёх машинах на человека это раздражает.

**Что дальше.** Централизованный реестр с подписью: сервер хранит
`repo_id → слепок артефактов`, клиент проверяет подпись. Подтверждение делает
человек один раз для организации, а не каждый для себя.

**Условие.** Больше десяти участников либо жалобы на повторные подтверждения.

## 4. LLM-слой детекции

Сейчас выключен (`policy.llm.enabled: false`, ADR-006). Механизм — нативные
`type: "prompt"` хуки, только на эскалацию из детерминированного слоя.

**Когда включать.** Когда `injection_scanner` упрётся в потолок точности:
доля ложных срабатываний перестанет снижаться правками правил, а доля
пропусков останется заметной.

**За чем следить после включения.** Доля вызовов, ушедших на эскалацию: порог
около 2% от общего числа. Выше — стоимость в токенах и задержка перестают
окупаться. Дефолтный таймаут 30 с делает LLM непригодным как единственный
контроль: G2 и G3 требуют детерминизма.

## 5. Парсер команд

**Ограничение сейчас.** Статический разбор принципиально не покрывает
динамически собранные команды; такие случаи документированы и уходят в `ask`.

**Триггер пересмотра.** Первый подтверждённый обход, не закрываемый правилом.

**Варианты.**

1. Внешняя проверенная реализация разбора shell вместо собственной.
2. Sandbox-исполнение вместо статического анализа: команда запускается в
   изолированном окружении, решение принимается по фактическим системным
   вызовам. Дороже, но снимает целый класс обходов.

Корпус обходов пересматривается ежеквартально независимо от инцидентов.

---

## 6. Statusline

Индикация состояния защиты в интерфейсе (`secure-dev: STRICT` в statusLine).
Приоритет P3: полезно для видимости, но не влияет на контроль. Реализуется
после того, как раскатка дойдёт до `strict` — раньше строка будет показывать
`AUDIT` и обесценит сама себя.

---

## 7. Agent Teams

Поля `agent_id` и `agent_type` в схеме аудита предусмотрены и заполняются уже
сейчас. Полноценная поддержка роя (агрегация по команде агентов, отдельная
политика для координатора) — вне периметра v2.0: механизм экспериментальный,
и подстраиваться под него до стабилизации API преждевременно.

---

## Что НЕ появится

Эти пункты закрыты решением, а не отложены:

- **Статический анализ уязвимостей в блокирующем хуке** (ADR-004). Точность
  regex на исходном коде без анализа потока данных принципиально низкая, а
  цена ложного срабатывания на записи файла — сломанный основной процесс.
- **Поддержка нативного Windows и PowerShell** (ADR-007). Второй лексер и
  удвоение корпуса тестов при нулевом приросте ценности, пока WSL доступен всем.
- **Контроль качества и дублирования кода.** Это задача `devflow`, а не
  безопасности.

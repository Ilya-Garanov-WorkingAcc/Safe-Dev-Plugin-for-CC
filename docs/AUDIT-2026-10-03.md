Проверялось рабочее дерево ветки `heredoc-data-and-banner` (2.1.2, не закоммичено).
Противник в модели — сам агент (в том числе под prompt injection) с инструментами
Bash/Write/Edit.

**Как проверялось.** Пять независимых аудиторов по зонам: парсер и правила команд,
секреты, недоверенный контент, самозащита и ядро, поверхность Claude Code по
документации. Опасные команды нигде не исполнялись: строки передавались хукам как
JSON, `HOME` и каталог данных — во временных каталогах. Главные находки первых
четырёх зон перепроверены отдельным стендом (пометка **[П]**); остальное — по
отчётам аудиторов (**[А]**). Пятая зона — пересказ документации Claude Code, не
перепроверялась (**[Д]**), в отчёте были неточности, поэтому на неё опираются
только там, где это сказано явно.

## 1. Главный вывод

Плагин надёжно ловит «прямые» формы опасных команд, но обходится тремя общими
способами, каждый из которых не требует изобретательности:

1. **Довести хук до таймаута.** Команда на 10–20 КБ разбирается дольше 5 с — лимита
   хука. По документации Claude Code хук, не уложившийся в таймаут, действие не
   блокирует [Д]. Fail-closed в коде покрывает исключения, но не таймаут.
2. **Спрятать команду в конструкцию, которую парсер не раскрывает:** `{ …; }`,
   `if …`, `${x:-$(…)}`, `bash -c -- '…'`, `env -S '…'`, `rm${IFS}-rf`.
3. **Отключить или ослабить сам плагин:** ни одно правило не защищает его файлы,
   настройки Claude Code, журнал и каталог состояния.

Отдельно: «карантин» репозитория ничего не блокирует, а доверие агент может
подтвердить себе сам.

### 2.2. Парсер команд: конструкции, скрывающие команду

Все строки ниже дают «нет решения» на любом уровне; `rm -rf ~` напрямую — deny.

| # | Класс | Примеры | Статус |
|---|---|---|---|
| P1 | Служебные слова и группы в позиции команды | `{ rm -rf ~; }`, `! rm -rf ~`, `if rm -rf ~; then :; fi`, `while …`, `coproc { … }` | [П] |
| P2 | Подстановка внутри `${…}` и в цели редиректа | `echo ${x:-$(rm -rf ~)}`, `echo x > $(rm -rf ~)`, `> >(…)` | [П] |
| P3 | Шелл с опциями и кодом из stdin | `bash -c -- '…'`, `bash <<< '…'`, `bash <(…)`, `fish -c`, `busybox rm -rf ~` | [П] |
| P4 | Динамическое имя команды без предупреждения | `rm${IFS}-rf${IFS}~`, `r${x}m`, `/bin/r?m`, `{rm,-rf,~}`, `x=rm; env $x …`, `set -- rm -rf ~; "$@"` | [П] |
| P5 | Обёртки, теряющие внутреннюю команду | `env -S '…'`, `env -C /tmp …`, `time -p …`, `chroot`, `flock`, `script -qc`, `watch`, `systemd-run`, `su -c` | [П] частично |
| P6 | Продолжение строки внутри комментария | `echo hi # x\` + перевод строки + команда | [П] |
| P7 | Переменная в цели `rm -rf` не считается динамической | `rm -rf "$X/"` (при пустом `X` это `rm -rf /` — класс инцидента 18.09) | [П] |
| P8 | Редирект слитно или в кавычках не распознаётся | `echo x>>~/.bashrc`, `echo x >"$HOME/.bashrc"` — правила persistence обходятся | [П] |
| P9 | `cwd == $HOME`: граница «вне рабочего каталога» становится всем домом | `rm -rf ~/projects`, `rm -rf .ssh`, `rm -rf *` | [П] |
| P10 | Запись файла и запуск одной командой | `printf '…' > run; bash run` (найдено ранее, до аудита) | [П] |

### 2.3. Логика политики

| # | Находка | Статус |
|---|---|---|
| L1 | Память сессии глушит повторный `ask`: `git branch -D x` → ask, повтор → без вопроса, причём отметка ставится в момент показа вопроса, а не после согласия. Подавленный `ask` заодно гасит эскалацию неразобранной команды (`git branch -D x; $X` → без вопроса). `policy.py:64-69`, `command_guard.py`. | [П] |
| L2 | Исключение `**/node_modules/**` сверяется только с первым операндом и по сырой строке: `rm -rf /tmp/a/node_modules/x /tmp/zz-victim` и `rm -rf /tmp/node_modules/../zz-victim` проходят. | [П] |
| L3 | Состояние сессии и кеш ветки git лежат в каталоге, куда агент может писать: заранее записанный `seen` убирает первый `ask`, подделанный кеш ветки понижает force-push в main с deny до ask. | [А] |
| L4 | Ошибка чтения `policy.json` → молчаливый дефолт `audit`; сломанный `rules/commands.json` → пустой набор правил, `rm -rf /` проходит. Печать покрывает только `policy.json`, а лок агент может пересчитать или удалить. | [А] |

### 2.4. Классы без правил

Перечислены классы, для которых в `rules/commands.json` нет ничего [А], выборочно [П].

- **Нерекурсивное удаление и перезапись вне рабочего каталога:** `rm`, `unlink`,
  `mv ~/.ssh /tmp/x` [П], `truncate`, запись `>` в произвольный путь, `dd of=<файл>`,
  `xargs rm` без `-I`, удаление `.git`.
- **git:** `checkout .` [П], `checkout -f`, `switch --discard-changes`,
  `restore -s`, `push origin +main` [П], `push --delete`, `push --mirror`,
  `stash drop|clear` [П], `reflog expire`, `gc --prune`, `update-ref -d`,
  `git -c alias.x='!…'`, `core.fsmonitor`, `core.hooksPath`.
- **Персистентность:** `~/.ssh/authorized_keys` [П], `~/.config/autostart`,
  `~/.config/systemd/user`, `~/.local/bin`, `.git/hooks`, `systemd-run`,
  `LD_PRELOAD`/`BASH_ENV`/`PROMPT_COMMAND`.
- **Windows-интероп из WSL:** `wslconfig.exe /unregister` [П], `cmd.exe /c wsl
  --unregister` [П], `powershell.exe -c …`, `wsl --shutdown`, `robocopy /MIR`,
  `diskpart`; каталоги `/mnt/c/backup/**` и `/mnt/c/recovery/**` не защищены.
- **Исполнение стороннего кода:** `curl … | python3` [П], `curl -o x && ./x`,
  `ssh localhost '…'`, `python3 -c` с `shutil.rmtree`/`os.remove`, `awk system()`,
  `sed e`, `tar --to-command`, `python3 file.py`, `make`, `npm run`.
- **Контейнеры, облака, БД:** `docker run -v /:/host …` [П], `--privileged`,
  `docker volume rm`, `kubectl delete`, `terraform destroy`, `aws s3 rm
  --recursive`, `DROP DATABASE`.
- **Привилегии и права:** `su`, `chmod u+s`, `setcap`, `chmod -R a+w ~`, запись в
  `/etc/wsl.conf` не редиректом (`cp`, `tee`, `sed -i`).
- **Следы:** `history -c` после перевода строки, `> ~/.bash_history`,
  удаление журнала плагина и транскриптов Claude Code.

Ложные срабатывания, найденные попутно: `git clean --dry-run -f` и `git push
--dry-run -f` дают deny.

### 2.8. Поверхность Claude Code [Д]

- Таймаут, падение и невалидный вывод хука действие не блокируют; `deny` сильнее
  `ask`, `ask` сильнее `allow`.
- Хуки работают и при `--dangerously-skip-permissions`; что происходит с `ask` в
  этом режиме, документация не уточняет.
- Не покрыты хуками плагина: NotebookEdit, Agent/Task, Skill, Monitor,
  планировщик; события `UserPromptSubmit`, `FileChanged`, `PostToolUseFailure`.
- `apiKeyHelper` и `statusLine` из настроек исполняются вне хуков.
- Запретить отключение плагина можно только управляемыми настройками
  (`/etc/claude-code/managed-settings.json`: `allowManagedHooksOnly`,
  `disableBypassPermissionsMode`, `strictKnownMarketplaces`).

## 4. Что осталось непроверенным

- Поведение Claude Code при таймауте хука и при `ask` в режиме обхода разрешений —
  известно только по документации, в живой сессии не проверялось. От этого
  зависит тяжесть всей группы T.
- Подгружает ли Claude Code вложенные `.claude/` и CLAUDE.md из подкаталогов —
  допущение аудитора.
- Находки с пометкой [А] воспроизведены аудиторами на стенде, но не
  перепроверялись повторно.
- Пробы аудиторов лежат во временном каталоге сессии и в репозиторий не
  перенесены; в корпус их нужно переносить по мере закрытия находок.

Готовый 3.0.0 прогнан четырьмя параллельными субагентами на живом плагине. Подтверждено: обходы парсера и защита по таймауту работают, ложных срабатываний почти нет, секреты детектируются, 17 батарей/e2e зелёные, латентность 64–81 мс.
Найдены и закрыты три проблемы (версия 3.0.1):
1. **Запись в защищённые каталоги Windows-диска мимо защиты.** Редирект (`>`/`>>`), `tee` и Write/Edit в каталоги улик/восстановления инцидента и системные каталоги не блокировались (ловились только rm/cp/mv). Добавлено правило path-windows-protected и редирект-glob в command-windows-recovery-path.
2. **Запись в persistence-файлы через Bash.** Дозапись в authorized_keys, tee, запись в .git/hooks шли мимо path_guard: правило path-persistence-write не включало Bash/bash_writers. Исправлено; то же для path-ssh-key.
3. **Ложное срабатывание на уборке сборки.** `cd <рабочий каталог> && rm -rf build` блокировалось как «вне cwd», потому что «вне» мерилось от каталога сессии, а не от каталога после cd. Теперь локальность цели считается от фактического каталога команды; удаление корня/дома/предка остаётся под контролем.
Также ужат regex secret-env-assignment (значение ≤ 256 символов) — на враждебном вводе он выходил за бюджет (0,56 → 0,15 с). Все находки покрыты регрессионными тестами (test_rules_p2, test_constructs).

# RUNBOOK.md — что делать при срабатывании

Разбор по классам правил. На этот документ ссылается поле `reference` каждого
правила, поэтому якоря разделов менять нельзя без правки `rules/*.json`.

Общий порядок один и тот же:

1. Прочитать сообщение целиком — там есть id правила и альтернатива.
2. Применить альтернативу.
3. Если не подходит — выполнить операцию самому в терминале.
4. Если правило сработало ошибочно — заявка в `#secure-dev`.

---

## secret-egress

**Что произошло.** В аргументах исходящего вызова (`Bash`, `WebFetch`,
`WebSearch`, MCP) обнаружен секрет. Команда не изменена — задан вопрос.

**Почему не блокируем.** Аутентифицированные вызовы — обычная работа.
Блокировка ломала бы её; вопрос стоит секунды.

**Что делать.**

- Подтвердить, если вы действительно отправляете эти данные по назначению.
- Отказаться, если секрет попал в команду случайно — например, был подставлен
  из вывода предыдущей команды.
- Перевести секрет в переменную окружения:
  `curl -H "Authorization: Bearer $TOKEN" …` вместо литерала.

**Если секрет уже ушёл.** Отзовите его. Ротация ключа занимает минуты, разбор
инцидента — недели.

## secret-output

**Что произошло.** В выводе инструмента найден секрет; модель видит
`[REDACTED:TYPE]` вместо значения.

**Что делать.** Обычно ничего: работа продолжается, модель просто не увидела
значение. Если значение нужно самой команде — передайте его через переменную
окружения, а не через вывод.

**Ложное срабатывание.** Чаще всего это правило `ENV_SECRET` на строке вида
`API_KEY=changeme` в примере конфигурации. Такие файлы стоит перечислить в
`policy.exclusions` — заявка в `#secure-dev`.

## config-trust

**Что произошло.** Репозиторий содержит `.claude/settings.json`, `.mcp.json`,
`.claude/hooks/` или `.claude/agents/` — то есть конфигурацию, способную
исполнять код, — и она не подтверждена на этой машине либо изменилась после
подтверждения.

**Почему это важно.** Хуки из настроек репозитория исполняются при старте
сессии, до того как содержимое кто-либо прочитал (CVE-2025-59536,
CVE-2025-59356, CVE-2026-21852). MCP-сервер из `.mcp.json` запускается своей
командой.

**Что делать.**

1. `/secure-dev:trust` — посмотреть перечень команд и URL.
2. Оценить каждую строку: обращение в сеть, чтение файлов вне репозитория,
   запуск интерпретатора — поводы отказаться.
3. Подтвердить, если конфигурация ожидаема для проекта.
4. Не подтверждать, если сомневаетесь: работать можно и без подтверждения.

**Расхождение с эталоном после подтверждения.** Сверьте с историей:

```bash
git log -p -- .claude .mcp.json
```

Если правку внесли вы — подтвердите заново. Если правка приехала с `git pull`
и вы её не ожидали — это повод для разбора, а не для повторного подтверждения.

## privilege

**Что произошло.** Агент попытался выполнить `sudo`, `doas` или `pkexec`.
Решение — отказ без возможности подтвердить.

**Почему так жёстко.** В типовой WSL-Ubuntu пользователь имеет passwordless
sudo. То есть `sudo` из агента отрабатывает молча и сразу даёт root:
необратимое разрушение вне `$HOME`, персистентность через cron и systemd,
отключение самих контролей, правка `/etc/wsl.conf` с выходом к дискам Windows.

**Что делать.** Выполнить команду самому в отдельном терминале. Реальная
потребность (`apt install`, `systemctl` для локальных сервисов) эпизодическая,
стоимость ручного выполнения — секунды.

**Рекомендация администратору.** Убрать `NOPASSWD` из `/etc/sudoers.d/` в WSL.
Это делает запрет двухслойным.

## command-destructive

**Что произошло.** Команда способна необратимо разрушить систему: удаление
корня или домашнего каталога, запись на блочное устройство, разметка диска,
форк-бомба, исполнение скачанного или декодированного кода в шелле,
`chmod 777`.

**Что делать по видам.**

| Сработало | Штатная замена |
|---|---|
| `rm -rf /`, `rm -rf ~` | Указать конкретный подкаталог: `rm -rf ./build` |
| Удаление вне рабочего каталога | Перейти в нужный каталог и удалять относительным путём |
| Цель удаления вычисляется на лету | Сначала `echo <выражение>`, убедиться, потом удалять |
| `dd of=/dev/…` | Писать в файл: `of=./image.img` |
| `mkfs`, `fdisk`, `parted` | Операции с разделами — вручную, вне агента |
| `curl … \| sh` | Скачать → прочитать → запустить тремя шагами |
| `base64 -d \| sh` | Раскодировать отдельно и показать результат |
| `chmod 777` | `chmod 755` для каталогов, `644` для файлов, `+x` для скриптов |

## git-destructive

**Что произошло.** Команда git способна уничтожить незакоммиченную работу или
переписать историю.

| Сработало | Штатная замена |
|---|---|
| `git checkout -- <путь>` | `git stash push -m "before-discard" -- <путь>` |
| `git restore <файл>` | То же; вернуть — `git stash pop` |
| `git reset --hard` | `git reset` без `--hard`; перед этим `git stash push` |
| `git clean -fdx` | Сначала `git clean -n`; нужное — в `.gitignore` или в коммит |
| force-push в защищённую ветку | Отдельная ветка и pull request |
| force-push в свою ветку | `git push --force-with-lease` |
| `git branch -D` | `git branch -d`; восстановить — по `git reflog` |
| `filter-branch` / `filter-repo` | Согласовать с командой: все клоны придётся пересоздать |

**Если работа уже потеряна.** `git reflog` хранит коммиты около 90 дней:
`git reflog` → `git checkout <hash>`. Незакоммиченные изменения без stash не
восстанавливаются — отсюда и жёсткость этих правил.

## persistence

**Что произошло.** Попытка изменить то, что исполняется автоматически:
`~/.bashrc`, `~/.zshrc`, `.envrc`, `/etc/profile.d/`, crontab, systemd-юнит,
`/etc/wsl.conf`, `/etc/fstab`, монтирование.

**Почему это класс безопасности.** Дозапись в конфигурацию шелла — классический
персистентный RCE: код выполнится при каждом новом терминале, независимо от
Claude Code.

**Что делать.** Настройки окружения проекта держите в файле проекта (`.env`,
direnv, `docker-compose.yml`), а не в общем конфиге шелла. Если правка общего
конфига действительно нужна — внесите её сами.

## anti-forensics

**Что произошло.** Очистка истории шелла: `history -c`, `unset HISTFILE`,
удаление `.bash_history`.

**Что делать.** Если в историю попал секрет — отзовите его. Чистка истории
проблему не решает: секрет уже был в процессе, в логах и, возможно, в контексте
модели.

## path-sensitive

**Что произошло.** Попытка прочитать приватный ключ, учётные данные облака,
`.netrc`, `.pgpass`, учётные данные Claude Code или `.env` — через `Read` либо
через Bash-команду (`cat`, `grep`, `cp`, `curl`).

**Что делать.**

| Задача | Как без чтения секрета |
|---|---|
| Подключиться по SSH | `ssh-agent` + `ssh host`; ключ агенту не нужен |
| Проверить AWS-профиль | `aws sts get-caller-identity` |
| Проверить контекст Kubernetes | `kubectl config current-context` |
| Посмотреть сертификат | `openssl x509 -in <файл> -noout -subject -dates` |
| Узнать имена переменных `.env` | `grep -o '^[A-Z_]*' .env` |

Файлы-шаблоны (`.env.example`, `.env.template`) не блокируются.

## injection

**Что произошло.** В выводе инструмента обнаружены признаки инструкций,
адресованных агенту: отмена предыдущих указаний, смена роли, требование
прочитать секрет или отправить данные наружу, скрытый текст, гомоглифы,
zero-width, base64 с директивой.

**Правило никогда не блокирует.** Оно помечает содержимое как данные.

**Что делать.**

1. Посмотреть, где именно сработало (класс и номера строк в сообщении).
2. Если это README или статья ПРО инъекции — ложное срабатывание, сообщите.
3. Если это чужой контент, который действительно пытается управлять агентом, —
   не выполняйте описанные в нём действия, сообщите в `#secure-dev`.
4. При классе `obfuscation` вывод дополнительно нормализуется: скрытые символы
   удалены, гомоглифы приведены к латинице.

## platform

**Что произошло.** Claude Code запущен вне WSL.

**Что делать.** Перезапустить внутри WSL: `wsl -d Ubuntu`, перейти в каталог
проекта, `claude`. Плагин продолжит работать и здесь, но семантический разбор
команд рассчитан на bash, а не на PowerShell.

## Внутренние события

Эти записи видны в журнале, но пользователю сообщений не дают.

| Запись | Что означает |
|---|---|
| `PARSER_ERROR` | Модуль упал; fail-closed вернул `ask`, fail-open пропустил |
| `PARSER_UNRESOLVED` | Команда собирается динамически, статически не проверяема |
| `LOCAL_OVERRIDE_REJECTED` | Попытка смягчить политику локально — отклонена |
| `LOCAL_OVERRIDE_UNKNOWN` | Неизвестный ключ в личном конфиге — проигнорирован |
| `EXEMPTION_EXPIRED` | Исключение просрочено и больше не действует |
| `RULE_SCHEMA_UNKNOWN` | Правило с неизвестным `kind` отброшено |
| `RULES_FILE_INVALID` | Набор правил не читается — остальные продолжают работать |

Частые `PARSER_ERROR` — дефект, а не шум: сообщите о нём, приложив команду.

# Сводка контроля secure-dev

Пользователь запросил отчёт по локальному журналу плагина.

## Что сделать

1. Выполни:

   ```
   secure-dev report ${1:---week}
   ```

2. Перескажи результат по-человечески, а не построчно. Что важно вынести:

   - **Топ сработавших правил** — какие срабатывания встречаются чаще всего.
   - **Ложные срабатывания.** Если правило срабатывает часто и всякий раз на
     штатной работе, это кандидат на доработку или на исключение, а не повод
     терпеть. На этапе калибровки такие случаи и есть главный результат.
   - **Латентность.** p95 выше 150 мс на PreToolUse — дефект, а не «медленно»:
     хук блокирует цикл агента.
   - **Пропуски heartbeat.** Отсутствие записей за рабочие дни означает, что
     плагин был отключён или не установлен.

3. Если пользователь готовит еженедельную сводку для руководителя — предложи
   отправить именно вывод `secure-dev report --week`. В нём нет ни содержимого
   диалога, ни секретов, ни путей к файлам проекта сверх метаданных операций.

4. При жалобах на ложные срабатывания предложи `/secure-dev:policy` — там
   описан порядок запроса исключения.

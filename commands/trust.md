# Доверие к конфигурации репозитория

Пользователь запросил проверку и подтверждение конфигурации репозитория
(`.claude/settings.json`, `.mcp.json`, `.claude/hooks/`, `.claude/agents/`).

Эти файлы приезжают вместе с клонированным кодом и исполняются при старте
сессии — до того, как их кто-либо прочитал. Именно так работают CVE-2025-59536,
CVE-2025-59356 и CVE-2026-21852.

## Что сделать

1. Выполни отчёт по репозиторию:

   ```
   secure-dev scan ${1:-.}
   ```

2. Покажи пользователю результат целиком, ничего не сокращая: перечень ключей
   и **конкретные команды и URL**, которые будут исполнены. Без них у человека
   нет основания принимать решение.

3. Если найдены исполняемые элементы — разбери каждый по существу: что делает
   команда, куда обращается URL, выглядит ли это ожидаемым для проекта такого
   рода. Отдельно отметь всё, что обращается в сеть, читает файлы вне
   репозитория или запускает интерпретатор.

4. **Решение принимает человек, и подтверждает он сам.** Не подтверждай доверие
   самостоятельно и не предлагай сделать это «чтобы не мешало». Команду
   `secure-dev trust` не запускай: из сессии агента она отказывается работать,
   а её вызов через Bash требует подтверждения человека.

5. Если пользователь решил доверять — назови команду, которую он выполняет в
   СВОЁМ терминале (не в этой сессии):

   ```
   secure-dev trust ${1:-.}
   ```

## Границы

- Подтверждение фиксирует слепок конфигурации. Любое последующее изменение
  переводит репозиторий в карантин и требует повторного подтверждения.
- Если пользователь сомневается — правильный ответ «не подтверждать»: работать
  можно и без доверия, ограничение касается только исполняемой конфигурации
  репозитория.
